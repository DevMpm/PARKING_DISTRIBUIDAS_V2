Módulo de Personas (/personas)

Operación Create (POST /personas)

CP1.1 Crear persona ok
Precondiciones: Token JWT con permisos suficientes (o acceso público según configuración del endpoint)
Entrada: JSON con datos válidos de persona (address: "Av. 10 de Agosto", dni: "1712345678", email: "juan.perez@example.com", firstName: "Juan", lastName: "Pérez", nationality: "Ecuatoriana", phone: "+593991234567")
Verificar:
1. Código de respuesta 201
2. Respuesta DTO con datos correctos de la persona creada.
3. Buscar por Id (GET /personas/:id) para confirmar su existencia.

CP1.2 Crear persona duplicada (DNI o email)
Precondiciones: Token JWT y una persona previamente registrada con DNI "1712345678" o email "juan.perez@example.com".
Entrada: JSON repitiendo el DNI o email existente.
Verificar:
1. Código de respuesta 409
2. Mensaje de error indicando conflicto (DNI o email ya existente).

Obtener Personas (Múltiples resultados)

CP2.1 Listar personas ok
Precondiciones: Token JWT con rol y permiso USUARIOS_READ, y personas registradas en el sistema.
Entrada: Ninguna (GET /personas)
Verificar:
1. Código de respuesta 200
2. Cantidad de registros obtenidos en el array acorde al total existente.

Obtener Persona Única

CP3.1 Obtener persona por ID ok
Precondiciones: Token JWT con rol y permiso USUARIOS_READ, y una persona creada.
Entrada: UUID válido de la persona como parámetro (GET /personas/:id)
Verificar:
1. Código de respuesta 200
2. Datos de la respuesta coinciden con la persona buscada.

CP3.2 Obtener persona por ID not found
Precondiciones: Token JWT con rol y permiso USUARIOS_READ.
Entrada: UUID inexistente como parámetro.
Verificar:
1. Código de respuesta 404
2. Mensaje de error indicando que la persona no fue encontrada.

CP4.1 Verificar si persona existe (Existe)
Precondiciones: Persona creada en el sistema.
Entrada: UUID válido existente en GET /personas/exists/:id
Verificar:
1. Código de respuesta 200
2. Respuesta JSON con { exists: true }.

CP4.2 Verificar si persona existe (No existe)
Precondiciones: Ninguna.
Entrada: UUID inexistente en GET /personas/exists/:id
Verificar:
1. Código de respuesta 200
2. Respuesta JSON con { exists: false }.

CP5.1 Obtener persona por DNI ok
Precondiciones: Token JWT con rol y permiso USUARIOS_READ, y una persona creada.
Entrada: DNI válido de 10 dígitos como parámetro (GET /personas/dni/:dni)
Verificar:
1. Código de respuesta 200
2. Datos de la respuesta coinciden con el DNI consultado.

CP5.2 Obtener persona por DNI not found
Precondiciones: Token JWT con rol y permiso USUARIOS_READ.
Entrada: DNI no registrado en el sistema.
Verificar:
1. Código de respuesta 404
2. Mensaje de error de persona no encontrada.

Actualizar Personas (UPDATE, PATCH)

CP6.1 Actualizar persona ok
Precondiciones: Token JWT con rol y permiso USUARIOS_UPDATE, y una persona creada.
Entrada: UUID de la persona como parámetro y DTO con campos actualizados válidos (ej. teléfono o email).
Verificar:
1. Código de respuesta 200
2. DTO de respuesta con los datos actualizados correctamente.
3. Buscar por Id (GET /personas/:id) para confirmar el cambio en la base de datos.

CP6.2 Actualizar persona not found
Precondiciones: Token JWT con rol y permiso USUARIOS_UPDATE.
Entrada: UUID inexistente y DTO válido.
Verificar:
1. Código de respuesta 404
2. Mensaje de error de persona no encontrada.

Eliminar / Desactivar / Activar Personas

CP7.1 Activar persona ok
Precondiciones: Token JWT con rol y permiso USUARIOS_UPDATE, y una persona previamente desactivada.
Entrada: UUID de la persona como parámetro (PATCH /personas/activate/:id)
Verificar:
1. Código de respuesta 200
2. Respuesta indicando éxito y confirmación de activación.

CP7.2 Activar persona not found
Precondiciones: Token JWT con rol y permiso USUARIOS_UPDATE.
Entrada: UUID inexistente en PATCH /personas/activate/:id
Verificar:
1. Código de respuesta 404
2. Mensaje de error.

CP8.1 Desactivar persona ok (Borrado lógico)
Precondiciones: Token JWT con rol y permiso USUARIOS_DELETE, y una persona activa.
Entrada: UUID de la persona como parámetro (PATCH /personas/deactivate/:id)
Verificar:
1. Código de respuesta 200
2. Respuesta indicando éxito y cambio de estado a inactivo.

CP8.2 Desactivar persona not found
Precondiciones: Token JWT con rol y permiso USUARIOS_DELETE.
Entrada: UUID inexistente en PATCH /personas/deactivate/:id
Verificar:
1. Código de respuesta 404
2. Mensaje de error.

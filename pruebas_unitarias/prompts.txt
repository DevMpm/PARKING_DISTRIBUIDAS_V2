------ Vehiculos Plan ----------------
Con base en la siguiente estructura y guía, crea una lista de casos de prueba "CP" para el módulo de vehículos en la carpeta @VehiclesNPM/vehiculos/src/vehiculos.

- Los casos de prueba corresponderán a pruebas de estilo REST sobre los diferentes endpoints en el archivo @VehiclesNPM/vehiculos/src/vehiculos/vehiculos.controller.ts. 

- Puedes revisar la lógica den todo el módulo de vehículos, @VehiclesNPM/vehiculos/src/vehiculos. Sin embargo, te recomiendo seguir esta estructura para definir los casos:

Endpoints/Operaciones Create

- CP Crear ok → Verificar 200, Respuesta con datos correctos, Buscar por Id para confirmar creación.
- CP Crear duplicado - Verificar 409 y mensaje de error.
- CP datos inválidos, Maneja al menos un caso por campo y constraint del DTO. → Verificar 400 y mensaje de error.

Endpoints/Operaciones Get que devuelven varios resultados.

- CP Buscar ok → Verificar 200 y cantidad de registros obtenidos en la consulta.
(Si buscan por un parámetro también va este caso:)
- CP Buscar sin resultados → Verificar 200 y cantidad de registros obtenidos (0).

Endpoints/Operaciones Get que devuelven un único resultado.

- CP Buscar ok → Verificar 200, Datos de la respuesta coinciden con parámetro de búsqueda.
- CP Buscar sin resultado → Verificar 404 y mensaje de error.

Endpoints/Operaciones de actualizar (UPDATE, PATCH)

- CP actualizar ok → Verificar 200, Datos de respuesta coinciden, Buscar por Id para confirmar el cambio.
- CP not found → Verificar 404 y mensaje de error.
- CP datos inválidos, al menos un caso por constraint del dto. → Verificar 400 y mensaje de error.

Endpoints/Operacioens de eliminar

- CP eliminar ok → Verificar 200, Buscar por Id para confirmar not found o cambio de estado si es eliminación lógica.
- CP eliminar not found → Verificar 404 y mensaje de error.  

Toma como referencia los archivos @cp_espacios y @cp_zonas para la elaboración de los casos y sigue su nomenclatura y estructura: Precondiciones, Entrada y Verificar. 

Genera únicamente la lista de casos en un archivo "cp_vehículos.txt" en la carpeta @pruebas_unitarias/, aún no escribas código de pruebas. 

- Considera que en vehículo se manejan 3 tipos, por lo que en los endpoints de crear y actualizar debes definir casos que consideren los campos y características únicas de cada tipo. Las características compartidas en vehículo pueden probarse una vez, pero las que son específicas de cada tipo deben probarse por separado.

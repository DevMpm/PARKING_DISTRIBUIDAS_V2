[Test Log - gestion-usuarios]
1. Fallo detectado en CP11.3 (GET /users/username/nonexistent): La prueba esperaba recibir un código HTTP 404 (Not Found) cuando un username no existe.
- Causa del fallo de lógica en el código fuente (`src/users/users.service.ts`): En el método `findByUsername`, se llama a `this.userRepository.findOne(...)` sin el operador `await`, por lo que el método retorna una promesa pendiente en lugar del resultado de la consulta o de lanzar `NotFoundException`, provocando que el controlador reciba una respuesta exitosa (200) en lugar de un error 404.

2. Fallo detectado en CP7.1 y CP8.1 (Activar / Desactivar Persona): La prueba recibe un error HTTP 500 (Internal Server Error) al intentar activar o desactivar una persona.
- Causa del fallo de lógica en el código fuente (`src/personas/personas.service.ts`): En los métodos `activate` y `deactivate`, el servicio llama a `this.userRepository.save(persona)` pasando una entidad `Persona` al repositorio de usuarios (`userRepository`), lo que provoca un error de restricción de base de datos (`null value in column "password_hash" violates not-null constraint`). Debería invocar `this.personaRepository.save(persona)`.

Siguiendo las directrices TDD, estos errores de lógica en el código de producción se documentan en este registro de fallos y no se fuerzan ni se modifican en `src/`.
